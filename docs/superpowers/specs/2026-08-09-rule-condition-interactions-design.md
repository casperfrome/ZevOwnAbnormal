# 规则条件交互修复设计

## 目标

修复编辑已有异常规则时“添加条件”按钮无响应、条件列表不显示的问题，并检查前端弹窗中同类的初始化顺序与按钮默认行为隐患。

## 根因

`openForm()` 在声明 `OP_LABELS` 之前调用 `updateFieldsForDataset()`。编辑已有规则时，后者会立即调用 `renderConditions()`；该函数访问仍处于暂时性死区的 `OP_LABELS`，触发 `ReferenceError`。异常中断了后续初始化，因此条件列表未渲染，“添加条件”等后续事件监听器也未绑定。

## 修复设计

1. 将已有数据集的初始化调用延后到条件渲染依赖、事件监听器和其他弹窗交互全部就绪之后。
2. 保持 `updateFieldsForDataset()` 作为数据集字段与条件列表的统一刷新入口，避免增加第二套初始化逻辑。
3. 为条件增删、分段选择、弹窗操作等非提交按钮显式设置 `type="button"`，防止这些控件未来处于表单上下文时触发默认提交。
4. 扫描其他前端模块是否存在“初始化调用早于 `const` 依赖声明”或动态表单按钮缺少显式类型导致的同类失效路径；只修复与本问题同类且可验证的项，不做无关重构。

## 测试

- 新增浏览器级前端回归测试：打开已有规则编辑弹窗时条件行正常出现；点击“添加条件”后条件行数量增加；逻辑切换和删除条件仍可用。
- 测试必须先在当前实现上以预期的 `ReferenceError` 或缺失条件行失败，再实施修复。
- 运行前端针对性测试、现有前端测试，并进行真实页面交互验证。

## 验收标准

- 编辑已有规则时原条件立即显示。
- “添加条件”每次点击新增一行，删除与 AND/OR 切换正常。
- 浏览器控制台无初始化异常。
- 同类初始化顺序问题完成扫描，相关回归测试通过。
